# Как поделиться игрой по ссылке

Внутренние пути `/workspace/...` относятся к облачной среде и не являются публичными ссылками для скачивания. Другу нужна опубликованная веб-версия игры.

Для игры из скачанного архива достаточно распаковать **Code → Download ZIP** и открыть корневой **`index.html`** двойным щелчком. Он включает все зависимости и работает без сервера. Перед отправкой новой версии выполните `npm run build`, чтобы обновить этот файл. Очистка кеша и сохранений для запуска не нужна.

Для GitHub Pages подготовлен `.github/workflows/pages.yml`. Он устанавливает зависимости, запускает unit-тесты, собирает игру и публикует только содержимое `dist/`. Исходный код, тесты и зависимости не входят в сайт. Отдельный сервер и ключи API не нужны.

Перед первой публикацией владелец репозитория должен включить **Settings → Pages → Build and deployment → Source → GitHub Actions**. Для приватного репозитория доступность Pages зависит от тарифного плана GitHub.

После согласованной отправки изменений в `main` workflow запускается автоматически. В разделе **Actions → Publish Deepforge to GitHub Pages** нужно дождаться завершения заданий `build` и `deploy`. Публичный адрес появится у окружения `github-pages` в результате `deploy` и в **Settings → Pages**. Отправляйте другу именно этот подтверждённый адрес, а не внутренний путь облачной среды.

Если Pages ещё не включён, сначала включите его в настройках, затем перезапустите неудавшийся workflow через **Re-run all jobs**. Последующие отправки изменений в `main` обновят сайт автоматически.

Подготовка workflow сама по себе ничего не публикует. Публикация делает игру доступной всем, у кого есть ссылка; пароль не предусмотрен.
